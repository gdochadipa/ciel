# Secretary security boundaries

The operator-controlled registry and Rust Core enforce access. Skills, model arguments, spreadsheet notes and remembered text grant no authority. Existing workbook tabs start read-only; structured writes require stable identity and a reviewed mapping.

Business HTTP calls require the Core bearer token bound to the sole owner. Approval uses a distinct operator token and immutable preview digest through an operator-only endpoint. The approval token is never a model tool input or response. Keep writes disabled until the trusted OpenClaw hook, owner identity, complete diff presentation, expiry, replay protection and restart behavior are qualified. A callback decision alone is not a signed approval proof. Transient previews are bounded to 64 entries/4 MiB serialized JSON per bridge, with expired entries reclaimed during preview/approval activity. Evicted previews must be fetched again before a new dialog; an open dialog retains its captured immutable preview. This is bounded operation state, separate from personal memory and the durable Core journal. Every mutation is recorded before provider execution; uncertain provider results require reconciliation and cannot be blindly replayed.

The bridge rechecks invocation authority after Core and scheduler responses as well as before requests. Pending results from a revoked invocation cannot be returned or cached as a preview. A dispatched mutation may still have taken effect before revocation; an error is not proof of rollback and requires state inspection before another attempt. Actual host lifecycle/cancellation behavior remains part of qualification.

Use a dedicated WhatsApp account, explicit owner DM admission and disabled inbound groups. Inbound `allowFrom` does not restrict outbound recipients. The bridge must enforce its own destination allowlist independently; examples in this repository are configuration templates, not active channel policy. Disable self-originated DMs for the dedicated assistant account. Skills cannot send vendor messages or change destinations.

Store runtime environment and service-account files outside the repository with owner-only permissions. Use distinct random Core and approval tokens; never print them during checks, log raw provider errors, place credentials in prompts, or copy them into fixtures. Bind the service to loopback and run it as a dedicated non-root account. Localhost still requires authentication.

Personal memory is OpenClaw-owned and outside the secretary plugin's tool surface. Configure and qualify the native host's memory permissions and automatic persistence policy separately; the plugin does not implement a lifecycle/history adapter. Source financial facts come from Sheets rather than conversation memory. Retain only necessary private data and define operational retention before activation.

The dedicated-runtime configuration template now explicitly disables compaction memory flush, Memory Core dreaming, internal directory hooks and the session-memory hook, and cross-conversation transcript recall. Its exact tool allowlist includes secretary tools, native memory search/get and session status; filesystem, shell/runtime, native automation and direct messaging tools are denied. The core `session_status` entry also keeps this from being a plugin-only allowlist. These are local template controls, not evidence about effective host permissions or installed providers. Plugin-managed hooks, per-agent/provider policy, existing scheduled jobs and enabled providers still require inspection. Transcript storage itself is separate from memory indexing. See the [pinned native memory assessment](native-memory-assessment.md) for supported controls and remaining gaps.

Production activation requires T007's actual runtime, Google, approval, scheduling and WhatsApp evidence. Local builds and HTTP stand-ins establish local behavior only. The subsequent low-effort code review and regression fixes do not establish a security audit or production certification.

T038 native discovery memory is separately opt-in and owner-private. The host selects the local agent workspace/audience; model arguments cannot set paths, model, TTL or note prose. The actual SDK safe-root rejects symlinks/hardlinks and bounds native files; notes are private and remain externally derived untrusted data. Explicit no-promotion policy is required before native effects. Native per-source exclusive locks and pending-operation tombstones fence source writes/cache refresh; unknown write state never licenses a second provider send. Cached discovery checks current registry and fixed seven-day expiry; generic native index/transcript copies are outside this TTL admission guarantee. No active memory provider, broad filesystem policy, automatic ingestion or scheduler is enabled by the feature.
