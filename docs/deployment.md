## Coherent journal backup

As the service user, create a mode-0700 backup directory on protected storage. Run `python3 scripts/backup.py /var/lib/secretary/secretary.sqlite3 /protected/backup/secretary-YYYYMMDD.sqlite3`. The script opens SQLite read-only, uses SQLite's backup API (including committed WAL content), checks integrity, and publishes the completed snapshot without overwriting an existing destination. It neither copies a live database file nor removes its WAL. Keep backup permissions private, define retention, and encrypt off-host storage before copying sensitive journals. Configuration/secret backups require separate protected handling; ordinary logs and repository artifacts must exclude them.

**Native scheduler backup remains a stop condition.** No version-qualified official scheduler backup/restore command was verified in this implementation. Do not copy/edit native job storage or claim a full-system backup. Consult the pinned official backup procedure and test a disposable restore before marking `backup_restore` complete. A Core journal snapshot alone is not a complete secretary backup.

For a journal restore, stop the service, preserve the failed state, validate the snapshot with SQLite, restore into a new protected state directory, and reconcile interrupted/uncertain operations before any writes. Keep the Core read-only and channels disabled while checking. Recover native scheduler jobs only through a qualified supported restore procedure, reconcile their IDs and cancellation state, then confirm owner-only delivery. Avoid automatically replaying provider writes or recreating canceled jobs. Restore testing and recovery timing remain pending until exercised on disposable resources.
