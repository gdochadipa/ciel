# General Workspace capabilities — T023

The owner requires a lightweight secretary usable across Sheets and Google Docs, with Google Docs editing included now. The wedding workbook is an optional business profile/regression fixture. One command bus, mutation coordinator, owner/approval flow and durable operation FSM serve all supported resources; no extra daemon, broker or read-store is required.

`config/workspace.example.json` is the generic operator catalog. `spreadsheets[].views[].kind: "grid"` registers a bounded A1 range (at most 10000 cells); the source tab ID/title and range remain operator-controlled. Reads preserve numbers/booleans/text/null and paginate/search literal values without guessing headers, currency, identities or report semantics. Grid reads need no frozen domain formula/merge template and are read-only. Existing structured schemas/domain profiles remain compatible and retain their write-preservation constraints.

`documents[]` registers aliases and Google Docs IDs with readable/writable flags. Writable defaults false. Google Docs tools list only registered aliases, describe tabs/revision and read bounded body-text excerpts, default 2000/max 10000 Unicode characters. All tabs are requested explicitly; tab IDs and source fingerprints bind pagination. Layout/non-text objects are not represented as faithful document rendering.

A Docs preview selects one tab and one action: append_text `{text}` or replace_text `{find,replacement}` with exactly one case-sensitive non-newline match. Preview captures the original body text, intended result, actor, target, expiry, mapping version and required Google revision. Global writes, resource writable permission and qualified owner approval all gate commit. Unsupported tables/non-text/suggestions/headers/footers/footnotes or absent revision disable edits rather than rewriting unknown structures.

One native batchUpdate request is sent with requiredRevisionId and explicit tab selection. A preflight source change conflicts; a native revision rejection is a known failure. Success requires observing the intended text. Ambiguous provider outcomes become uncertain and cannot be resent; operator reconciliation observes content only. A matching result establishes the intended text state, not attribution of a collaborator's identical edit. Legacy Sheets persistence/digests remain compatible; public Docs previews use document/tab names.

The body projection is bounded to 128 KiB across 100 tabs/depth 16 and provider JSON to 2 MiB. New text max 8192 bytes; find max 2048 bytes. The full preview must fit the qualified trusted UI without truncation; these limits are not measured CPU/token/heap savings. Generic rich-format editing, Docs creation/Drive enumeration, arbitrary batch requests and schema-free Sheets writes are outside this slice.

The Google adapter chooses readonly/write scopes independently for registered readable Sheets and Docs capabilities. Standard user cost constraints remain: no paid-tier activation or paid quota increase. Live Docs API enablement, resource ACL/scopes, actual host owner approval presentation and preservation remain separate gates. Existing operator-reported Sheets metadata success does not qualify Google Docs. Committed defaults stay off; live writes need disposable resources and target-specific qualification.

Primary contract sources checked 2026-10-28: [Docs get](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/get), [tab handling](https://developers.google.com/workspace/docs/api/how-tos/tabs), [batchUpdate revision control](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/batchUpdate), [insert/replace requests](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/request). The machine contract is [openapi.yaml](../../contracts/openapi.yaml).

## T025 — create a bounded tab in an existing registered spreadsheet

Two tools share the existing bus/coordinator/journal/FSM: `sheets_preview_create_tab` accepts `{operation_id,spreadsheet,title,rows,columns,headers?}`; `sheets_create_tab` accepts only `{operation_id}`. This creates a tab inside the registered spreadsheet, never a new spreadsheet file. Both global writes and the spreadsheet's explicit `create_tabs: true` are required; the flag defaults false and requires readable registration. It is separate from structured-row write permission. Shipped examples keep it false.

Title: 1–100 Unicode characters, no surrounding whitespace, controls or `[]:*?/\`. Dimensions: 1–1000 rows, 1–26 columns, at most 10000 initial cells. Optional headers: at most one per column, each at most 256 UTF-8 bytes without controls, written as `stringValue` (including strings starting `=`), never formulas. Preview contains the full literal header list, generated nonnegative 31-bit sheet ID, dimensions, spreadsheet ID/alias, owner, expiry, registry version and resulting access policy. Registered view titles/IDs and all observed tab titles/IDs are checked for collision; title checks conservatively ignore case. A collision fails; there is no suffixing or silently choosing a different target after approval.

Resulting access policy is **unregistered, readable=false, writable=false**. Core never edits its registry or grants a new view automatically. An operator must separately add a bounded `grid` view (and change registry version/restart) to permit reads. Generic grids still cannot receive arbitrary writes; structured-write registration retains its existing schema constraints. Creation permission grants bounded internal metadata/header verification only; catalog contents are not exposed as an unrestricted read tool.

One Sheets `batchUpdate` contains `addSheet` with the approved ID/title/dimensions and optional `updateCells` for row-zero literal headers. Google validates and applies a batch atomically. Core checks current ID/title collisions before sending, then observes exact ID/title/GRID dimensions and headers (including blank trailing columns). Metadata is read without grid contents; verification fetches only the new tab's first row, bounded to 26 columns. Provider JSON remains capped at 2 MiB and each call at ten seconds; no write retry is added.

Replay returns the persisted preview or applied state. Uncertain/failed commits cannot begin another send. Interrupted/ambiguous outcomes use the shared recovery and operator-only reconciliation route; absent tabs stay in reconciliation, changed identity/title/dimensions/headers conflict. Observation establishes the intended current state, not attribution of an identical collaborator-created tab. Sheets has no conditional create bound to the metadata snapshot; concurrent collisions are rejected by the provider's explicit ID/title constraints. Collaborator edits after creation may require manual resolution, never automatic deletion/recreation. No existing tab is modified by the request.

Official sources checked 2026-10-28: [AddSheetRequest and UpdateCellsRequest](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/request), [batchUpdate atomicity](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate). Local/synthetic evidence does not qualify live OAuth/API/ACL, quota, owner UI or preservation. T007 must exercise this capability on an explicitly disposable spreadsheet before activation; no live mutation is authorized here.

## T027 — bounded literal grid updates

Grid views remain read-only unless the operator explicitly adds `writable_range` wholly contained in the registered read `range`. The range uses full A1 rectangles (single cell: `B2:B2`). No tab creation or model request grants this permission; shipped workspace examples omit it. Global writes and qualified owner approval remain required.

Use existing `sheets_preview_change` with `action: "update"`, no `record_id`, and exactly `fields: {range,values}`. Supply a complete rectangular matrix for one target of at most 100 cells, within the write range. Values are literal UTF-8 text (<=2048 bytes), finite safe numbers (absolute value <=9007199254740991), booleans or explicit null (clear). Before/after entered-value matrices are each capped at 16 KiB serialized; rich values/formulas/partial rows are rejected. Strings beginning `=` stay text. There are still 25 tools; append and structured schemas retain their existing semantics.

Current formula/unsupported entered values, overlapping merges, registered headers/formulas from any view on the same sheet and overlaps with structured views are protected. The preview captures exact raw entered before/after values and binds owner, view, spreadsheet+sheet identity (`record_id` is `spreadsheetId:sheetId` for sheets_grid only), mapping version, request, expiry and full source fingerprint. Legacy Sheets JSON/request digests remain compatible through a distinct sheets_grid resource tag.

Commit revalidates permission, target, registry and source, then sends exactly one native batchUpdate/updateCells with sheet ID, start coordinates, complete rows and `fields: userEnteredValue`. It preserves formatting and does not insert/delete rows or change other cells. Empty cell data with that field mask clears entered content. Provider rejection is a known failure; malformed/lost/server responses are uncertain and cannot be resent. Reconciliation observes entered values only: intended state applies, old state remains unresolved, other states conflict. It proves current state, not attribution of a collaborator's identical edit. Sheets has no compare-and-swap for this request: a human edit between preflight and send can still race; this is not a transaction guarantee.

Primary contract: [UpdateCellsRequest](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/request#UpdateCellsRequest). Local HTTP/provider and SDK fixtures do not qualify live Google, target host approval rendering or production activation. VPS work remains deferred by the owner; production write and qualification defaults stay off.

## T028 — registered Docs text search

Use docs_search with `{document,query,tab_id?,limit?,cursor?}`. Search is read-only and limited to one operator-registered readable document, with no Drive enumeration or arbitrary ID/URL. Omitted tab_id searches all projected body tabs in provider traversal order, including nested tabs; an explicit tab must exist. Matches are literal, case-sensitive, nonoverlapping and in text order. Query is nonblank and <=256 UTF-8 bytes. No regex, case folding or Unicode normalization is applied.

Default limit10, maximum50. Each result gives tab ID/title, exact match start/end, snippet start/end and text with at most 80 Unicode scalar values of context per side (<=416 scalars total). Displayed document/tab titles are limited to 200 scalars. Offsets are zero-based, end-exclusive Unicode scalar positions in the existing body projection; they are not native Google UTF-16 editing indices or layout locations. Headers/footers/non-text objects are outside body-text coverage; tables follow the same flattened projection as docs_read.

The common source includes document identity, revision, full source fingerprint, mapping version and retrieval timestamp. Pagination binds identity, exact query, selected tab, registry version and source fingerprint; changed source/query/tab cursors fail stale_cursor. Existing <=128 KiB projected text, 100-tab and 2 MiB provider limits apply; no search index, personal-memory store, write/approval state or additional Google scope is created. Existing owner authorization and Docs-specific live qualification remain required. There are 26 tools. CI/VPS work remains deferred by the owner.

## T029 — optional case-insensitive Docs search

Set case_sensitive:false on docs_search to match Unicode case variants; omitted/true preserves T028 behavior. The option must be a boolean (null/strings/numbers are rejected). Input query remains literal, nonblank and <=256 UTF-8 bytes, with exact input spelling and effective mode bound to the cursor. Switching modes or changing query spelling invalidates a cursor, even when folded queries are equal; omitted and explicit true remain cursor-compatible.

Matching uses locale-independent full Unicode case folding via pinned unicase 2.10.0, including expansions (Straße/STRASSE), dotted-I expansion and Greek final sigma. No Unicode normalization, accent removal or locale-specific Turkish mapping is performed. Complete folded matches must start/end at original scalar boundaries; a single s does not match half of ß. Matching remains nonoverlapping in original text order. Returned snippets keep original spelling/case and original scalar offsets; folds are only temporary per-read matching data, with no persisted index or journal state. All T028 limits, owner/registration checks and body-only projection boundaries remain unchanged; 26 tools, no new Google scope or write.

Dependency reference: [UniCase folding API](https://docs.rs/unicase/2.10.0/unicase/struct.UniCase.html). The locked Rust dependency is used for Unicode semantics rather than ad hoc lowercasing tables. Its full three-scalar expansion is covered by a real public HTTP regression.

## T032 — offline draft view registration

An operator can explicitly add a bounded generic grid view to an existing registered spreadsheet in a new offline candidate, using `registry add` with kind `grid_view`. The parent's readable/create_tabs flags and old grants remain unchanged; the new view has no writable_range/write_schema and inherits parent readability. New ranges on a readable parent therefore extend declared read access only in that candidate, requiring separate review/installation; no live config reload is performed. Tab identity conflicts and duplicate view names fail closed, while consistent ID/title pairs can have multiple bounded named ranges. No provider tab/file creation or automatic registration occurs as part of a mutation. See [registry setup](../registry-setup.md) and [T032](../../.scratch/secretary-mvp/T032.md).

## T033 — explicit search across registered Docs

Existing docs_search now also accepts documents: an ordered list of one to three distinct readable registered aliases, mutually exclusive with document and tab_id. No implicit all-documents/Drive discovery. Query, case_sensitive (default true; false uses the existing Unicode folding), global limit (default10/max50) and cursor are supported. Every registration is checked before provider IO. Reads are sequential, bounded by existing per-document limits and a four-second aggregate async deadline; provider failure, identity drift, unsupported projection or timeout rejects the whole page without partial snippets. This is a bounded read, with no new scope, journal, index, memory or approval state; 26 tools remain.

Results order follows the explicit documents list, then provider tab/text traversal. Each match adds document alias; sources lists evidence for all selected documents, including those with no returned match. Snippets/offsets remain per-tab projected Unicode scalars, body text only. At most limit+1 matches are materialized. Multi cursors bind ordered aliases, exact query/mode, mapping version and every document identity/full source fingerprint; even an unseen source change invalidates the cursor. Reads from separate documents are not an atomic Google snapshot. Legacy document input/result/cursor behavior stays unchanged. Inputs must choose one selector; no tab_id filter is supported for the multi-document mode. Development evidence is local/synthetic, not live Docs/host qualification.

## T035 — explicit search across registered Sheets views

Existing sheets_search also accepts targets: one to three distinct ordered `{spreadsheet,view}` alias pairs, mutually exclusive with legacy spreadsheet/view input. Names are nonblank <=100 UTF-8 bytes, query nonblank <=256 UTF-8 bytes, global limit default50/max100. Existing Sheets literal lowercase matching of typed field values is reused; no new Unicode full-fold/normalization/regex mode. Every readable parent and view is checked before provider IO. Each distinct workbook is fetched once per request, sequentially, under a four-second aggregate async deadline, preserving registered ranges and whole-workbook validation. Any provider/identity/template/deadline error rejects the entire page.

Records retain fields/source and add spreadsheet/view aliases. sources contains evidence for every selected view, including registered range, provider/tab identities, fingerprint, mapping version and retrieval time. Order is explicit targets then existing projected record order; distinct overlapping views can intentionally return the same cells. Global pages are limited to100 records and128KiB serialized data; oversized pages fail without truncating fields. Cursor binds exact ordered targets/registered view definitions, exact query/mode, mapping version and all full workbook fingerprints, including unreturned sources. Separate workbook reads are not atomic. Legacy one-view response/cursor behavior stays unchanged; coverage registered_views_only, match_mode literal_case_insensitive_lowercase. No discovery, journal, index, new tool/scope/daemon or live write is added; 26 tools and qualification gates remain unchanged.
