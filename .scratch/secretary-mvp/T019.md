# T019 — Built entry registration and approval integration

Date: 2026-10-26. Depends on T003/T006/T017. Status: passed locally; live host activation remains T007. Continues the owner's preference for local preparation.

## Gap and change

Previous simulated-provider acceptance invoked `createSecretary` directly. SDK type/build/package validation had passed, but did not execute the built entry's actual registered factories and hook together. This left lazy credential capture, shared preview state and registration preservation dependent on separate checks.

`scripts/acceptance-entry.ts` loads the built distribution entry and actual installed OpenClaw SDK. A deliberately minimal registry collects the real SDK's factory and hook registrations; it is a host boundary fixture, not a substitute SDK or live Gateway. The write acceptance launcher now builds the current entry before starting services and runs the entry exercise after the existing stateful workflow. HTTP fetch, Core/journal and Google-only simulation are unchanged and run for real.

The exercise verifies SDK-recognized authoring metadata and all 17 tool factory registrations, credential/runtime-free registration and concrete factory construction, invocation-time synthetic credential capture, result text/details agreement, owner and revoked-invocation errors, unrelated-hook pass-through, missing/wrong requester and action rejection, and preview isolation between host API instances. A preview returned through the factory is changed by the test caller; the hook still presents the captured original digest/diff. Its one-shot approval callback reaches actual Core, the registered append succeeds, and repeated append observes the same outcome with exactly one matching record. Synthetic credentials are restored/removed in a finally block. No model, Gateway job or live approval UI is run.
