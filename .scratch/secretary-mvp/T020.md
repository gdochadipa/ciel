# T020 — Bound transient approval-preview state

Date: 2026-10-26. Depends on T003/T013/T019. Status: passed locally; T007 live qualification remains open.

## Problem and behavior

The bridge retained every successfully fetched approval preview until a decision, even after expiry. A long-running host API could accumulate operation snapshots without a cache limit. This is transient operation state; personal memory remains entirely OpenClaw-owned.

The cache now keeps at most 64 entries and 4 MiB of serialized UTF-8 JSON per bridge/host API. Capturing a preview or preparing approval removes expired entries. Re-fetching an operation replaces its cached capture and refreshes recency; new captures evict oldest captured entries until both limits fit. Cache eviction requires fetching a preview again before opening a new approval dialog, without deleting Core's durable operation/audit history or replaying provider work. Invalid/expired or individually over-budget previews are not retained for approval.

Already-open dialogs keep their original cloned immutable preview, digest, expiry and one-shot callback; cache eviction cannot alter that snapshot. Host-retained dialogs are outside this cache budget. The serialized-byte limit is not a measured heap/RSS ceiling. Cleanup is bounded activity-driven work with no background timer, embedding/index processing or second persistent memory store.
