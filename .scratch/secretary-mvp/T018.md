# T018 — Operator gate and coherent journal recovery

Date: 2026-10-26. Depends on T005/T007/T017. Status: local checks passed; full-host recovery remains T007. Owner explicitly requested continuing local preparation before live qualification.

## Defect and change

The existing backup script used SQLite connection context managers as if they closed connections. They only manage transactions. New CLI regressions reproduced leftover `.secretary-backup-*-wal` and `-shm` files after both a successful backup and an overwrite refusal. The actual Core journal backup/restore test reproduced the same failure independently in Linux.

The script now uses `contextlib.closing` to close both handles before publication and converts the temporary destination to DELETE journal mode. This produces a standalone, integrity-checked snapshot and removes temporary sidecars before fsync/link publication. Existing destination files are still never overwritten, source connections use read-only mode, and error output still omits paths/private details.

## Executed evidence

- Ten Python operator CLI tests passed as a non-root user on native macOS and qualified Linux. They exercise real subprocesses/private files: complete synthetic attestation, incomplete/wrong-version/malformed qualification, public/symlinked files and state, unsafe tokens, duplicate/unsupported env lines, mock mode/enabled-write rejection, invalid registry/credential shape, committed WAL versus uncommitted data, snapshot permissions/no overwrite/cleanup, and corrupt/missing source failure. No live credentials or external service was used.
- The new Rust integration test backs up an open actual Core WAL journal containing an approved operation in `applying`, verifies overwrite refusal/source preservation, restores into another directory and reopens via the production Journal. Digest and approval audit survive; state becomes `reconciliation` and `begin_apply` rejects replay. It invokes the real Python backup CLI, not an SQLite substitute for Core.
- Full production Rust graph formatting, Clippy with warnings denied and all 22 Rust tests passed in the network-isolated qualified container. No production Rust implementation changed.
- `scripts/verify.sh` now runs the Python operator suite. The previous T017 SDK/34 TypeScript/six simulated-provider results remain applicable to unchanged plugin/provider code; those checks were not rerun for this operator-only slice.

## Limits

A valid synthetic attestation proves only that the local preflight accepts the documented file contract; it does not qualify an actual host. The Python happy-path test skips under root because deployment requires a non-root service user; the recorded runs were non-root with no skips. The Rust restore test requires Python3, already used by the verification workflow. Recovery uses disposable synthetic journals only, with no provider request or side effect replay.

Native scheduler backup/restore, live owner approval/channel routing, service-account OAuth, target-host sandbox behavior and full deployment recovery remain unqualified. [T007](T007.md) now records each gate and the evidence still required. No capability flags, personal memory store, production configuration or workbook changed.
