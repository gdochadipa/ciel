# T024 — Require separate Google Docs operator qualification

Status: local checks passed, 2026-10-28. Depends on T007/T018/T023. Target-host qualification remains open.

## Problem and change

T023 added independent Docs capabilities, but preflight still accepted a Sheets-only operator attestation with a readable Docs registry. Deployment prose asked the operator to combine both into the old field, so the local gate could not distinguish absent Docs evidence.

Preflight now requires a nonblank string `evidence.google_disposable_docs` when any registered document is readable, including with global writes disabled. The existing Sheets field and all previous gates remain intact. Registries without readable Docs need no new evidence. Ambiguous/non-boolean capability flags, non-array document registration and writable-without-readable entries fail closed rather than skipping the new gate. Core remains responsible for complete registry validation.

The qualification template adds an empty Docs evidence field, with `qualified: false`. Deployment guidance and T007 now identify separate Docs API/ACL/scope, tab/revision, preservation and reconciliation evidence. Passing this check establishes only that a private operator attestation is present; it does not prove live behavior or authorize deployment.

## Executed evidence

- Added public CLI regressions before the fix. The previous script wrongly returned success for Docs without valid evidence and malformed capability flags; the tests failed with return code 0 instead of 1.
- All 13 operator CLI tests pass as a non-root user on native macOS and qualified Linux (network-disabled Docker). No skips. They include missing/null/blank/non-string Docs evidence, accepted separate synthetic attestation, unreadable Docs/legacy compatibility and malformed flags, plus the existing token/file/state/backup regressions. Denial output remains generic and excludes synthetic private values.
- Python syntax, qualification JSON, changed local Markdown links and Git whitespace checks passed.
- Rust/plugin runtime and provider code are unchanged, so their T023 full verification and seven simulation results were not rerun. The existing SDK archive remains unchanged.

No credentials, target resources, real services, native jobs or messages were accessed. No paid service or billing/quota setting changed. Live Docs ID and target-host connection are still unavailable; T007 remains open.
