# T031 — Add resources to an offline registry draft

Owner request: make adding Sheets/Docs to a draft registry easier. Depends on T030.

## Contract

- Same one-shot offline Core CLI: `registry add --config BASE --resource ADDITION --output NEW` (fixed option order, paths only; private IDs stay in JSON).
- Addition JSON: `{"version":"new-version","resource":{"kind":"document","alias":"notes","id":"doc-id"}}`, or kind `spreadsheet` with alias/id and `views:[{"name":"overview","sheet_id":0,"title":"Sheet1","range":"A1:D20"}]`.
- Strict input fields, no permission knobs. Construct a document with readable/writable false or spreadsheet with readable/create_tabs false and bounded generic grid views, empty headers/merges/formulas, no write schema/range. Existing resources and permissions are retained semantically.
- Require a nonblank version different from the base. Shared Registry::validate remains authoritative for bounds, IDs/aliases, view names, tab IDs/titles and grid ranges. Collisions reject the addition; no merge/replace or automatic suffixing. One new resource per invocation; at most 20 resources and 10 views per spreadsheet under existing rules.
- Both input files use T030 bounded <=1 MiB regular/no-final-symlink/nonblocking file reads. Validate the complete candidate before creating output. Serialized candidate <=1 MiB; exclusive output, Unix 0600-or-stricter, never overwrite even a symlink/base/resource path. A write failure can leave a partial new file.
- Emit sanitized aggregate counts/fixed codes only, no IDs/names/versions/paths/raw parser diagnostics. Base and addition stay unchanged. No Google/network, env/credential loading, journal/listener, active configuration install/reload or activation. No new plugin tools; 26 retained.
- This adds new registrations only. Adding views to an existing spreadsheet, discovery/URL resolution and enabling access remain explicit manual work outside this slice. Operator verifies private provider IDs/tab IDs/titles; this command does not verify live identity or access.
