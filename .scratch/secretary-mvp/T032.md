# T032 — Append a grid view to an existing draft spreadsheet

Owner selected easier tab/view registration for an already registered spreadsheet. Depends on T031.

## Contract

- Extend the same offline `registry add --config BASE --resource ADDITION --output NEW` with strict JSON `{"version":"new-version","resource":{"kind":"grid_view","spreadsheet":"operations","view":{"name":"stock","sheet_id":8,"title":"Stock","range":"A1:D20"}}}`.
- Select an existing spreadsheet by its exact registered alias, including unreadable draft registrations. Never create a missing parent, select Docs, change the parent's ID/flags, or silently merge/replace/rename views. Missing target uses fixed `registry_spreadsheet_not_found`.
- Append exactly one generic bounded grid view, with empty header/merge/formula metadata and no write_schema/writable_range. Existing resources, views and grants are retained semantically. The new view inherits the parent's readable flag in the candidate; this is explicit bounded draft registration, not a separate per-view read permission or active configuration change. Existing overlapping write grants are retained, but no new write grant is added.
- Permit a new tab identity, or an additional named range on an already mapped tab when exact numeric ID and title agree. Reject same ID with a different exact title or same ASCII-case-insensitive title with a different ID (`registry_view_identity_conflict`). No provider lookup/rename inference. Reject duplicate view names and >10 views via the shared Registry validator; preserve other Core range/title/ID rules.
- Reuse nonblank/different version checks, actual Registry validation, bounded/no-final-symlink/nonblocking input reads and exclusive Unix 0600-or-stricter <=1 MiB output from T031. Inputs unchanged; all validation before output creation; output aliases/symlinks/replay cannot overwrite. Partial output remains possible only on write failure.
- Private addition file supplies alias/ID/title/range, never commandline values or output diagnostics. Fixed errors/counts only; no environment/credential loading, Google call, journal/listener, active installation/reload/activation or new plugin tools. Provider tab creation remains a separate preview/approval/FSM operation; this only registers a view in a candidate.
