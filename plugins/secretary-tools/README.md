# Secretary OpenClaw bridge

Owner-only plugin for registered Google Sheets, Google Docs and native reminders, targeting the actual **OpenClaw 2026.10.7** SDK. The 26 tools use one loopback Rust Core for deterministic reads and controlled writes. Wedding-specific views/reports are optional domain profiles; general resource access uses `config/workspace.example.json`.

## Resource capabilities

| Capability | Tools and limits |
| --- | --- |
| Google Sheets | `sheets_list/describe/read/search` read registered views. Generic `grid` views preserve typed values within an operator-selected range of at most 10000 cells and require no wedding headers/formulas. Generic grids are read-only by default, with optional bounded writable_range for approved literal updates; existing explicit structured write schemas use `sheets_preview_change/append/update`. |
| Google Docs | `docs_list/describe/read/search` discover registered aliases, tab IDs and bounded body-text excerpts. Default 2000/max 10000 Unicode characters per read; cursor binds source fingerprint and registry version. Search accepts a case-sensitive literal query (<=256 UTF-8 bytes), optional tab ID and default 10/max 50 results, with bounded snippets and source-bound pages. Offsets are Unicode scalars in projected text, not Google edit indices. No Drive enumeration or model-selected document URL. |
| Docs edits | `docs_preview_change` supports `append_text` with `{text}` and `replace_text` with `{find,replacement}` for one exact case-sensitive match in a selected tab. `docs_apply` commits the approved operation ID. Tables, non-text objects, suggestions, headers/footers/footnotes and missing revisions disable edits; read coverage is body text, not layout. |
| Operation history | `operations_get_history` reads the shared Sheets/Docs journal; `sheets_get_history` remains a compatibility tool. An uncertain write requires operator reconciliation, never blind retry. |
| Optional profile | `reports_wedding` requires a registered wedding-cost view. It is not a general resource schema. |
| Native reminders | `reminders_create/list/get/reschedule/pause/resume/cancel/history` use supported native Gateway RPC, with separately qualified scheduler access. |

Docs provider JSON is capped at 2 MiB, projected text at 128 KiB across at most 100 tabs, tab nesting at 16. Insertion/replacement text is at most 8192 bytes; the find string is at most 2048 bytes and cannot span newlines. Forbidden control/private-use insertion characters are rejected. Full immutable previews remain subject to qualified, complete host display; these bounds are not a token/RSS guarantee.

## Owner and approval

Trusted factory context supplies `requesterSenderId`, `senderIsOwner` and invocation guards. Tool inputs cannot supply actors, credentials, hosts or outbound destinations. Authority is checked before requests and after responses; revoked pending results cannot return data/cache previews. A dispatched mutation may already have occurred, so inspect/reconcile its outcome.

The bridge defaults to `http://127.0.0.1:8787`, permits literal loopback HTTP only and rejects redirects. It reads distinct Core/operator bearers from `SECRETARY_CORE_TOKEN` and `SECRETARY_APPROVAL_TOKEN` lazily at invocation. Request limit 64 KiB, response limit 2 MiB, bridge timeout 5s; raw provider errors/tokens are omitted. Core remains authoritative for schema, immutable intent, actor/action binding, expiry, audit and single-use commit.

`approvalTransportQualified` defaults false and blocks Sheets commits and `docs_apply`. The registered `before_tool_call` hook presents the captured original preview and permits only allow-once/deny. Callback failures block resolution; denial/expiry/replay do not grant commit authority. Qualify owner-only routing, full rendering without truncation, callback failure behavior and restart handling in the actual host before enabling. No model `approved` flag is accepted.

The shared preview cache holds at most 64 captures/4 MiB serialized UTF-8 JSON per host API. Preview/approval activity removes expired captures; fresh captures evict oldest when needed. Re-fetch an evicted preview before opening another dialog. An already-open dialog retains its original one-shot snapshot outside the cache budget. No cleanup timer or personal-memory database is added.

Docs commits use Google's `requiredRevisionId`, explicit tab selection, one batchUpdate send and subsequent text observation. Concurrent changes detected before send become conflict; native revision rejection is a known failure and cannot be replayed. Accepted-but-lost response becomes uncertain; reconciliation observes the expected text without resending. Legacy Sheets journal JSON/digests are preserved by a defaulted resource-kind tag.

## Native reminders and memory

`schedulerQualified` defaults false. Reminder create uses owner-scoped declaration keys, exact offset timestamps or numeric five-field cron (default Asia/Makassar), bounded paginated discovery and no blind retry after uncertain add. Updates forward the observed native configRevision. Discovery caps 200 jobs/page, ten pages and 2 MiB; malformed/nonadvancing cursors or duplicate IDs abort before mutation. Offset pages are not a transactional snapshot.

Jobs use main-session system events only with `deleteAfterRun:false`; completion and delivery evidence remain separate. Cancel disables and retains native identity/history with a description marker; explicit resume clears it. Repeated create reconciles retained canceled jobs without reactivation. Resume/reschedule reject changed payload/session/delivery routes; pause/cancel can still stop such jobs. Unknown revisions disable edits. Jobs deleted outside the bridge cannot be recovered. Native persistence, convergence and actual owner-only WhatsApp delivery remain T007.

Personal memory belongs to OpenClaw. The plugin registers no memory tools or preference store; native memory policy/permissions are qualified separately. Domain facts come from fresh registered sources. The dedicated runtime template keeps bounded native retrieval and explicit-saving safeguards, without granting shell/file writes to the model.

## SDK and verification

The entry uses public `defineToolPlugin`, TypeBox schemas and context factories. Extending the original register function preserves SDK authoring metadata and the approval hook. Metadata loading/factory construction needs no credential or runtime service. Strict type checks use the actual installed SDK, never substitute declarations.

From this package: `bun run check:types`, `bundle`, `build`, `validate`, `pack`. Build performs strict types, bundle and actual host build; pack also validates before producing the host archive. Node range `>=24.22.1 <25 || >=26.12.1`; qualified Node24.22.1/Bun1.2.21. Install actual frozen dependencies first. The SDK archive contains manifest, minimal package metadata and bundle; npm dry-run separately selects four files including README. Pack refuses existing output; retain/move it before producing another archive. No install/enable/reload/publish action is included.

[Local verification](../../docs/local-verification.md) documents isolated reproduction. `bash scripts/verify.sh` checks Rust/operator/plugin/SDK behavior; `bash scripts/acceptance-all.sh` runs seven Google-only scenarios. `workspace` exercises real generic Sheets and Docs handlers, stateful Google revisions/lost responses and actual SDK registrations against a host registry fixture. Core is never a simulation member. These checks do not qualify live Docs scopes/permissions, actual approval UI, native Gateway or channels.

Current implementation/evidence is recorded in [T023](../../.scratch/secretary-mvp/T023.md) and [implementation status](../../docs/implementation-status.md). Production writes and capability flags remain off; no live document, spreadsheet, job, message or host configuration was changed.

Tab creation (T025): `sheets_preview_create_tab` takes `{operation_id,spreadsheet,title,rows,columns,headers?}` for an existing registered spreadsheet with explicit `create_tabs: true`. `sheets_create_tab` consumes its approved operation ID. Initial size is <=1000 rows, <=26 columns, <=10000 cells; optional headers are literal text. The complete preview binds the generated sheet ID, title, dimensions and access policy. The new tab remains unregistered/readable=false/writable=false; an operator must explicitly register bounded access afterward. Never create a new operation ID to work around uncertainty: inspect shared history and use operator reconciliation, which observes without another send. Committed flags stay disabled. See [capability bounds](../../docs/specs/workspace-capabilities.md).

T027: registered grid views can opt into literal cell updates using an operator `writable_range` contained in their read range. Use `sheets_preview_change` action update, omit record_id, fields `{range,values}` for one complete rectangle <=100 cells; `sheets_update` commits its immutable approved operation. Null clears, `=` strings remain literal. Protected formula/merged/header/structured targets fail closed. No permission is granted by creating a tab. After ambiguity, use operation history and operator reconciliation; never resend. Shipped defaults stay off. See capability bounds for preview limits and the preflight race limitation.

Docs search example input: `{ "document": "notes", "query": "meeting", "limit": 10 }`. Supply tab_id to search one tab, or omit it to search all projected body tabs. Query matching is case-sensitive and literal. Results include bounded snippets, tab IDs/titles and match/snippet offsets; use the unchanged query/tab and returned cursor for the next page. Changed sources reject the cursor. The search tool does not require approval credentials or create an operation.

Optional case-insensitive search (T029): `{ "document": "notes", "query": "MEETING", "case_sensitive": false }` also finds Meeting/meeting. Omitted or true keeps the previous behavior. Unicode case folding preserves original display text and offsets; no normalization/accent removal is applied. Use the same mode and exact query spelling when paging. No approval token, write or new tool is needed.

For cross-document search, pass `docs_search` `{documents:["notes","reference"],query:"meeting",case_sensitive:false,limit:10}`. Select one to three distinct registered readable aliases explicitly; omit document/tab_id. Results have a global limit, each match identifies its document, and sources contains evidence for every selection. Pages follow selection/tab/text order; cursor binds all sources and the exact query/mode. A provider failure or four-second Core aggregate deadline returns an error without a partial page. Single-document input/cursor behavior remains compatible. No Drive discovery, index, new scope or write is added.

For selected Sheets search, use `sheets_search` `{targets:[{spreadsheet:"operations",view:"overview"},{spreadsheet:"archive",view:"overview"}],query:"meeting",limit:10}` and omit top-level spreadsheet/view. Select one to three distinct registered readable view pairs explicitly; each name is <=100 UTF-8 bytes. Query <=256 UTF-8 bytes uses existing Sheets literal lowercase matching across typed fields. Global pages default50/max100 records, add aliases per record and evidence for every selected view, and bind every source/target/query to the cursor. Overlapping distinct views may return the same cells separately. Each workbook is fetched once per request; provider/deadline errors or multi pages >128KiB reject the whole page, never truncate records. Single-view input/cursor remains compatible; no additional scope/discovery/write.

For a source-backed Docs summary, call `docs_read` `{document:"notes",mode:"summary_context",max_characters:6000}` and omit tab_id/limit/cursor. Core returns fair bounded tab excerpts S1..Sn, source evidence, scalar spans, continuation cursors and explicit projected-body coverage. OpenClaw's existing model composes the summary with citations and a source legend; no model service/credentials are added. Partial or empty context is disclosed, and source text/titles remain untrusted data. Legacy tab reads still work. See [Docs summary workflow](../../docs/docs-summaries.md); source skill guides are not automatically installed/qualified by the archive.
