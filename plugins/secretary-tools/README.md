# Secretary OpenClaw bridge

Thin mixed tool/hook plugin targeting **OpenClaw 2026.10.7**. Host SDK imports live only in `src/index.ts`; `src/bridge.ts` is the public operation adapter and has no SDK substitute. Package peer version is exact. The installed SDK and generated type declarations are unavailable here; the entry has **not been compiled against actual SDK types or activated**. Node 24.16+ and the pinned OpenClaw package are deployment prerequisites. Do not interpret passing pure tests as host compatibility proof.

Owner identity comes from factory `OpenClawPluginToolContext.requesterSenderId` plus `senderIsOwner === true`. Every operation rejects absent/mismatched identity. The Core bearer and separate operator approval bearer come from `SECRETARY_CORE_TOKEN` / `SECRETARY_APPROVAL_TOKEN`; neither appears in a tool schema. Core URL defaults to `http://127.0.0.1:8787`, matching the Core listener, and is operator configuration limited to literal loopback HTTP IPs; redirects are rejected. Requests cap at 64 KiB, responses at 2 MiB, timeout defaults to five seconds. No automatic retries, particularly after uncertain mutations. Public errors omit raw upstream messages and credentials.

The eight `sheets_*` tools and `reports_wedding` call authenticated Core `/v1/tools/{name}` routes. Mutation inputs reject unknown keys. Core remains authoritative for schema field validation, immutable preview state, audit, expiry, actor binding and single-use commit.

`approvalTransportQualified` defaults false, disabling commits. The trusted `before_tool_call` hook requires the configured owner requester and a locally captured Core preview. It requests only `allow-once` or `deny`; closure data is cloned and authorization persists to the separate approval endpoint with the Core digest. Preview cache loss requires a new preview. No model-provided approval flag is accepted. The host callback does not identify the approving responder: **do not enable the flag until live qualification proves owner-only approval routing, full immutable preview display, deny/timeout behavior, callback failure blocking, restart handling, and no allow-always path**. This is an operator qualification flag, not evidence that transport is already qualified.

`reminders_create/list/get/reschedule/pause/resume/cancel/history` call verified `api.runtime.gateway.request` cron methods; `schedulerQualified` defaults false. No custom scheduler or native persistence files are used. Creates use stable owner-scoped `declarationKey`, list-before-add reconciliation, exact timestamp with offset or numeric five-field cron, and Asia/Makassar default. Existing conflicts require reconciliation instead of blind duplication; uncertain add is never retried automatically. Native IDs manage lifecycle. New jobs set `deleteAfterRun:false`; completed one-time jobs remain available for history. Cancel disables a job and records `Secretary: canceled; retained for history` in its native description instead of removing it. Explicit resume clears that marker. Creation retries reconcile retained jobs without re-enabling them. These operations return the native updated job, not a deletion receipt. Jobs removed outside the bridge and jobs already deleted by older versions cannot be recovered by this change. Native history retention limits still apply. Payloads are main-session system events only; there is no LLM-controlled recipient/channel or explicit outbound send. These wake the agent and **do not prove WhatsApp delivery**. Run evidence is returned with separate status/completion/delivery fields untouched. Verify Gateway authority, persistence after restart and owner outbound routing before enabling. Native job execution and later agent/channel policy still require deployment qualification.

`memory_capabilities` reports unavailable. Mutation/search lifecycle APIs, provenance/history and automatic-save opt-out have not been verified. Do not substitute a separate memory database or infer that casual conversation authorizes saving; defer memory tools until a bounded native adapter is qualified.

## Checks

Run `bun test plugins/secretary-tools/test` from repo root for pure owner/policy/native RPC adapter tests. Run `SECRETARY_HTTP_TESTS=1 bun test plugins/secretary-tools/test` in an environment permitting loopback bind for actual HTTP stand-in tests, including immutable preview approval. This sandbox prohibits bind (`PermissionError: Operation not permitted`; Bun reports EADDRINUSE), so HTTP tests are opt-in and unverified here. Gateway test doubles are only external RPC boundary contracts, not live host evidence.

No production call, WhatsApp send, live cron job, secret or user configuration is changed by this package. Deployment must run the pinned SDK's build/validate commands and verify actual exported types; no ambient fake module declarations are supplied.
