# Secretary OpenClaw bridge

Thin mixed tool/hook plugin targeting **OpenClaw 2026.10.7**. Host SDK imports live only in `src/index.ts`; `src/bridge.ts` is the public operation adapter and has no SDK substitute. Package peer version is exact. The installed SDK and generated type declarations are unavailable here; the entry has **not been compiled against actual SDK types or activated**. Node 24.16+ and the pinned OpenClaw package are deployment prerequisites. Do not interpret passing pure tests as host compatibility proof.

Owner identity comes from factory `OpenClawPluginToolContext.requesterSenderId` plus `senderIsOwner === true`. Every operation rejects absent/mismatched identity. The Core bearer and separate operator approval bearer come from `SECRETARY_CORE_TOKEN` / `SECRETARY_APPROVAL_TOKEN`; neither appears in a tool schema. Core URL defaults to `http://127.0.0.1:8787`, matching the Core listener, and is operator configuration limited to literal loopback HTTP IPs; redirects are rejected. Requests cap at 64 KiB, responses at 2 MiB, timeout defaults to five seconds. No automatic retries, particularly after uncertain mutations. Public errors omit raw upstream messages and credentials.

The eight `sheets_*` tools and `reports_wedding` call authenticated Core `/v1/tools/{name}` routes. Mutation inputs reject unknown keys. Core remains authoritative for schema field validation, immutable preview state, audit, expiry, actor binding and single-use commit.

`approvalTransportQualified` defaults false, disabling commits. The trusted `before_tool_call` hook requires the configured owner requester and a locally captured Core preview. It requests only `allow-once` or `deny`; closure data is cloned and authorization persists to the separate approval endpoint with the Core digest. Preview cache loss requires a new preview. No model-provided approval flag is accepted. The host callback does not identify the approving responder: **do not enable the flag until live qualification proves owner-only approval routing, full immutable preview display, deny/timeout behavior, callback failure blocking, restart handling, and no allow-always path**. This is an operator qualification flag, not evidence that transport is already qualified.

`reminders_create/list/get/reschedule/pause/resume/cancel/history` call verified `api.runtime.gateway.request` cron methods; `schedulerQualified` defaults false. No custom scheduler or native persistence files are used. Creates use stable owner-scoped `declarationKey`, list-before-add reconciliation, exact timestamp with offset or numeric five-field cron, and Asia/Makassar default. Existing conflicts require reconciliation instead of blind duplication; uncertain add is never retried automatically. Native IDs manage lifecycle. New jobs set `deleteAfterRun:false`; completed one-time jobs remain available for history. Cancel disables a job and records `Secretary: canceled; retained for history` in its native description instead of removing it. Explicit resume clears that marker. Creation retries reconcile retained jobs without re-enabling them. These operations return the native updated job, not a deletion receipt. Jobs removed outside the bridge and jobs already deleted by older versions cannot be recovered by this change. Native history retention limits still apply. Payloads are main-session system events only; there is no LLM-controlled recipient/channel or explicit outbound send. These wake the agent and **do not prove WhatsApp delivery**. Run evidence is returned with separate status/completion/delivery fields untouched. Verify Gateway authority, persistence after restart and owner outbound routing before enabling. Native job execution and later agent/channel policy still require deployment qualification.

`memory_capabilities` reports unavailable. Mutation/search lifecycle APIs, provenance/history and automatic-save opt-out have not been verified. Do not substitute a separate memory database or infer that casual conversation authorizes saving; defer memory tools until a bounded native adapter is qualified.

The [pinned native memory assessment](../../docs/native-memory-assessment.md) records available read interfaces and the remaining lifecycle gaps. The dedicated-runtime template disables documented automatic-saving paths and denies general write/shell tools; it does not qualify native memory mutations or change a live host.

## Checks

Run `bun test plugins/secretary-tools/test` from repo root for owner/policy/native RPC adapter tests and approval checks using synthetic Core responses at the fetch boundary. These approval checks do not execute Core or the host SDK. Run `SECRETARY_HTTP_TESTS=1 bun test plugins/secretary-tools/test` in an environment permitting loopback bind for actual HTTP stand-in tests, including immutable preview approval. This sandbox prohibits bind (`PermissionError: Operation not permitted`; Bun reports EADDRINUSE), so HTTP tests are opt-in and unverified here. Gateway test doubles are only external RPC boundary contracts, not live host evidence.

The approval description carries the entire cloned Core preview as JSON, rather than relying on a previous message. The selected tool must match the preview action. Core refusal throws from the callback; a successful callback returns no payload. Deny records rejection using the captured digest; timeout, cancellation and allow-always never send approval. A callback is single-use even if the request fails. The [documented hook contract](https://docs.openclaw.ai/plugins/hooks/tool-policy) guides the decision types and warning severity. Pinned SDK compilation, owner-only routing, complete rendering without truncation and host callback-error blocking remain qualification requirements.

No production call, WhatsApp send, live cron job, secret or user configuration is changed by this package. Deployment must run the pinned SDK's build/validate commands and verify actual exported types; no ambient fake module declarations are supplied.


## Reminder reconciliation and updates

Scheduler discovery requests at most 200 jobs per page, ten pages total and 2 MiB across responses, with disabled jobs included. The adapter follows explicit `hasMore`/`nextOffset` hints when supplied; without them it advances full pages by their row count. A malformed/nonadvancing cursor, repeated native ID, response overflow or page overflow stops discovery before any mutation. Owner filtering happens after discovery. Offset pages are not a transactional snapshot: duplicate detection catches some concurrent movement but cannot prove that no row was skipped. The actual pinned host response shape, creation convergence and concurrent native edits remain live qualification cases.

Pause/resume/reschedule/cancel require a nonempty native `configRevision` and forward it as `expectedConfigRevision`. Missing revisions leave the job readable but disable edits. No retry occurs after a rejected or uncertain update; read current native state before deciding on a new request. Resume/reschedule refuse jobs whose native payload/session/delivery no longer match the secretary's main-session system-event profile. Pause/cancel can still stop such a job. Trusted invocation guards run during discovery and immediately before mutations so an expired tool context cannot continue after an awaited lookup.

The pinned [v2026.10.7 protocol schema](https://github.com/openclaw/openclaw/blob/v2026.10.7/packages/gateway-protocol/src/schema/cron.ts) verifies request pagination fields, job revision fields and the update revision parameter. External Gateway fixtures test adapter behavior through the public tool interface; they do not establish installed SDK compatibility, native persistence or actual WhatsApp delivery. Google-only Postman simulations are unchanged by this native RPC slice. No host/runtime is mocked and reported as activated.

Gateway availability is awaited before scheduler access, matching the pinned [runtime type](https://github.com/openclaw/openclaw/blob/v2026.10.7/src/plugins/runtime/types.ts). An asynchronous false result cannot authorize RPC; invocation authority is checked again after availability resolves. Local fixtures cover both available/unavailable results and revocation while awaiting availability.


## Discovery and packaging

The manifest declares all 18 runtime tools in `contracts.tools`, has explicit startup activation when the plugin is enabled, and leaves both capability flags off. Declaration is ownership metadata; it grants no tool permission, owner identity or write approval. Runtime registration and metadata checks share the exported tool catalog, while the manifest remains a standalone JSON artifact the host can read before loading code. The [pinned capability contract](https://github.com/openclaw/openclaw/blob/v2026.10.7/docs/plugins/manifest/capabilities.md) requires runtime registrations to match the manifest's tool names.

From the repository root, `bun run check:plugin` checks this repository's metadata invariants without importing the host SDK, reading credentials or connecting to a runtime. It checks tool ownership, identity/version consistency, the built runtime entry, owner config, disabled defaults, pinned host requirement and the exact distribution file allowlist. It is not a replacement for host validation.

From this package directory:

- `bun run bundle`: metadata checks plus SDK-external JavaScript bundling; no SDK compatibility claim.
- `bun run build`: bundle, then the actual host's documented plugin build command.
- `bun run validate`: metadata checks and host validation of the explicit built entry.
- `bun run pack`: full build and host validation before the documented host pack command. It cannot proceed when the host command is missing or fails.

The [pinned CLI reference](https://github.com/openclaw/openclaw/blob/v2026.10.7/docs/cli/plugins.md) documents build/validate/pack and explicit root/entry options. No install, enable, reload or publish action is part of these scripts. The `files` allowlist selects only `dist/index.js`, this README and the manifest; npm also includes package metadata. Development scripts and source remain checkout-only.

An offline npm dry-run checks both synthetic private-file exclusion and the actual local package selection. It neither executes the bundled entry nor produces an activated plugin. The independent `plugin-source` CI job checks these local guarantees without waiting for Rust locks/SDK installation; the existing full verification/release job still requires qualified dependency locks and the actual host. Hosted CI has not been run here.
